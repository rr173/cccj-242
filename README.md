# 离线数据交换平台：可重开的有序访问数据集

各区域已排好序的估价分布分片在此汇成一个**可重开的有序访问数据集**。
行不展开权重，下游可反复按**全局加权位置**或**估值**取记录，两种查询共享同一套
秩定义，可互相交叉核对。

## 数据模型

- 分片 = 来件标识(`sender`，即分片身份) + 独立编号的记录 + 有序行；
  行 = `(记录号, 估值, 正整数权重)`。
- 估值为固定比例的带符号 64 位整数；`null`/`None` 表示未知值，未知值统一并列且排在最后。
- 全局次序：估值升序(未知居末) → 分片标识(字节序) → 源行号(分片内次序) → 副本位 `0..权重-1`。
  分片内同值行不要求先按记录号排序；不同分片的同值行组成一个连续全局并列组。
- 同值总权重与全局位置可超过 SQLite 有符号整数上限：所有权重与前缀和以十进制文本
  落盘，在 Python 大整数上运算；估值本身不含权重，限定在 int64 域。

## 关键设计

- **磁盘只存输入行与持久索引，不按权重扩张**：`rows` 每行存分片内局部前缀和
  `wsum_before`，配 `(sender, is_unknown, valuation, row_idx)` 索引与
  `UNIQUE(sender, record_no)`。
- **全局秩不落地**：查询时把至多 64 个活跃分片的局部前缀和相加合成。
  因此单分片更正只 `DELETE`+`INSERT` 该分片自己的行——不重读未更正分片的记录，
  也不逐条重写后续全局秩；后到分片的更正自然改变后续全部秩。
- **小页定位不重数**：位置→估值在估值域上二分(每步一次跨分片索引求和)，
  分片内用前缀和二分定位首行，不从第一组或第一源行重新计数。
- **流式构建/更正**：逐行验证(升序、未知居末、正整数权重、记录号唯一——
  唯一性由磁盘索引强制)，内存 O(1)，允许巨大同值组。
- **声明语义**：同身份同内容的重复声明幂等只算一次；同身份异内容、逆序、
  非法权重、同分片记录号重复均拒绝构建；不同身份下相同字段值仍分别贡献。
- **更正语义**：`correct_shard` 原子替换同一分片(新旧版本不同时贡献)，
  新版本完整验证失败则回滚、仍用以前的库；只维护当前版本。
- **可重开**：数据集是单个 SQLite 文件，新进程打开即可查询，不访问输入分片。

## API

```python
from ordered_exchange import Dataset, ShardError, load_shard

ds = Dataset.create("data.db", [load_shard("left.json"), ...])  # 建库
ds = Dataset("data.db")                                         # 重开

ds.declare_shard(sender, rows)   # "inserted" / "duplicate"；冲突抛 ShardError
ds.correct_shard(sender, rows)   # 原子更正；验证失败抛 ShardError，旧库不变

ds.rank_interval(value)  # value=None 指未知组
# -> {"present", "start", "end", "weight", "insertion"}
#    缺席值：present=False，区间为空 [insertion, insertion)

ds.slice(position, length)  # 零基全局加权位置 + 请求长度
# -> [{"sender","record_no","source_row","value","weight",
#      "group":(g,g+w), "span":(rs,re), "replicas":(lo,hi)}, ...]
#    每条来源记录给并列组半开秩区间与被覆盖的副本位区间，不逐副本输出
```

## 两期迁移台账

两期估价分布关账后，`build_ledger` 对照两份数据集库与一份转列清单，
生成一份可独立核对的 SQLite 台账，分清**声明转列 / 默认承接 / 退出 / 新增**：

```python
from ordered_exchange import build_ledger, Ledger, LedgerError

summary = build_ledger("old.db", "new.db", "transfer.jsonl", "ledger.db")
# -> {"entries", "kinds": {"transfer","carry","exit","new"},
#     "declarations", "records": {"old","new"},
#     "total_weight": {"old","new"}}

with Ledger("ledger.db") as led:     # 只读打开，不需要输入库与清单
    led.verify()                     # 独立核对：不一致抛 LedgerError
    for e in led.entries("transfer"): ...   # 逐笔明细，line_no 回查清单行
    led.region_totals()              # 按 (旧地区, 新地区) 组合精确合计
    led.sender_totals(0)             # 旧期各地区总权重（1=新期）
```

- **清单格式（JSONL，可为空、可无序，空行跳过但计入行号）**：
  `{"old": {"sender","record_no","start"}, "new": {...}, "length"}`；
  `start`/`length` 为十进制整数字符串，`length` 必须为正；副本位从零起，
  是记录内位置。声明把两端等长半开区间按相对顺序一一对应。
- **校验**：端点记录必须存在、区间不得越过该记录权重；同一期同一记录内
  任意两条声明不得占用同一副本位（重复声明也算冲突，首尾相接合法）。
  坏行、找不到端点、越界、重叠——整份台账不交付，错误指出清单行号。
- **默认承接**：未被声明占用的位置，仅当两期都有同一 `(sender, record_no)`
  且同一副本位两端都空闲时配成一对；余量不压紧再配，不按估值猜测。
  旧端余量记退出，新端余量记新增。
- **台账内容**：`entries` 明细以区间为单位，给出存在一侧或两侧的记录标识、
  估值、起始副本位与共同长度；缺端整组为 NULL，估值未知是
  `is_unknown=1` 且 `valuation` 为 NULL，二者分得开。`records` 登记两期
  全部记录，`region_totals`/`sender_totals` 为精确合计（退出缺新地区、
  新增缺旧地区）；按任一侧汇总即还原该期各地区总权重。
- **交付**：只读打开两份输入库；台账先建临时文件，完成后原子链接到目标
  路径——半成品不出现在目标路径，已有目标不覆盖。全程按区间处理，
  不逐副本展开；权重、副本位、合计可超 int64，以十进制文本落盘。
  声明与记录流式处理，内存占用与声明总数、单记录声明数无关。

台账内大整数副本位按 `(length(start), start)` 排序即数值序
（`entries_old_idx`/`entries_new_idx` 已建此序索引）。
```

## 驻留资格判定

核算组要在本期挑出已在同一地区连续留存满指定期数的库存。`residency_report`
沿一份或多份相邻期台账，把末期记录的每个请求区间逐段回溯，交付一个新的
JSONL 文件：

```python
from ordered_exchange import residency_report, ResidencyError

summary = residency_report(
    ["ledger1.db", "ledger2.db"],   # 按闭账顺序；第 1 份连接第 0、1 期
    3,                              # 最低连续闭账期数（正整数）
    "requests.jsonl",               # 末期待核清单
    "report.jsonl")                 # 交付路径；已存在则拒绝覆盖
# -> {"out", "requests", "segments",
#     "verdicts": {"符合", "不符合", "历史不足"}, "ledgers"}
```

- **请求**：每行 `{"sender", "record_no", "start", "length"}`，start/length
  为十进制整数字符串（起点非负、长度为正），指定末期记录内的半开副本位
  区间。各行独立，重复或相交的请求各自出结果；空行跳过但计入行号。
- **台账链**：第一份台账旧侧为第 0 期，第 i 份连接第 i-1、i 期。相邻两份
  在共用期的记录登记逐条一致（标识、权重、估值；未知只与未知相同——总量
  相等不能代替这项检查），不一致不交付并指出共用期期号。只读使用既有台账，
  不打开原始数据集或转列清单，也不重新核算单份台账。
- **判定**（以末期所在地区为准，按台账明细确定实际前身）：默认承接与同地区
  转列都延续驻留——换号、偏移变化、估值变化不重新计时；最近一次跨地区转列
  或没有旧端的新增是驻留起点，自其发生后的闭账期计满第一期（退出后同号再
  新增不承接旧库存）；同地区前身能追到第 0 期的只确认从第 0 期起的下限。
  确切期数或已知下限达到门槛判「符合」，确切不足判「不符合」，只有下限且
  不足判「历史不足」。
- **交付**：每行一个末期子区间 `{"line_no", "sender", "record_no", "start",
  "length", "verdict", "periods", "exact", "basis"}`；start/length 为十进制
  字符串，`exact=false` 时 periods 是下限。`basis` 定位驻留起点（或窗口最早
  闭账期）的期号、记录与子区间起点；由转列或新增确定起点的附该台账（第
  period 份）的 `entry_id`。按请求行号、区间起点有序，每条请求不重不漏；
  相邻两段结论、依据期号、记录、明细引用相同且依据端副本位连续时合为一段，
  否则分开。记录找不到、坏行、区间越界或共用期不一致时不交付结果，已有目标
  不覆盖，目标路径不出现半成品。
- 全程按区间流式处理：副本位与权重可超 int64，不逐副本展开，不在内存保留
  整期记录或明细、全部请求或某条热点记录的全部明细与追踪片段。

可复跑的小例子：`python3 examples/residency_example.py` —— 同一条请求
因中途转入与持续留存被拆成「符合」与「不符合」两段。

## 审批合并

两位核算员从同一份转列批件出发，各交回一份已试算成功的修订稿。
`merge_approvals` 只读原批件与左、右两份各自经 `build_ledger` 生成的
台账（不访问原数据集或原清单），判定两份修订能否共同出账：

```python
from ordered_exchange import merge_approvals, ApprovalError

summary = merge_approvals(
    "base_ledger.db", "left_ledger.db", "right_ledger.db",
    "merged_manifest.jsonl",   # 可出账时交付：可直接传给 build_ledger
    "disputes.jsonl")          # 待协调时交付：完整争议明细
# -> {"status": "可出账" | "待协调", "out", "declarations",
#     "resolved_segments", "old_records",
#     "disputes": {"old": n, "new": n}}
```

- **前置核对**：三份台账的旧端记录登记必须逐条相同，新端登记也必须逐条
  相同（记录标识、权重、估值；未知估值只等于未知）。不符即报错，指出哪份
  稿、哪一端、哪条记录，不交付任何文件。台账只读，调用期间不变。
- **判定单位是旧端副本位**，比较三稿在该位的指向（新端记录标识与副本位，
  未声明则无指向）。双稿指向一致（含都未声明、都撤回）就采用；仅一稿与原
  批件不同时采用变更稿（含撤回）；两稿都变且指向不同即**旧端争议**——一方
  撤回、另一方改派也不能自动合并。
- **新端相容**只检查已经判定的指向：同一新端副本位被两个或更多旧端副本位
  占用即**新端争议**（同一旧端记录的不同位置也算不同占用者）；有旧端争议
  的位置不参与、不猜测去向，旧端争议也不掩盖其他已能确定的新端争议。
- **合并对象仅 transfer 申报**：carry/exit/new 不是审批指令，合并清单投入
  核算后这些非声明明细仍由原有核算规则确定；未声明的区间不进清单。
- **争议明细（JSONL）**：有争议时只交付它，不交付全量或部分清单。先列旧端
  争议（`type:"old"`，写旧端区间及 base/left/right 在段首的指向，无指向为
  `null`），再列新端争议（`type:"new"`，写新端区间及各占用者对应的旧端
  区间）。两类各按争议端记录标识、数值起点排序，占用者按旧端同一次序排序；
  相接的争议段在每个选项/占用者另一端记录不变且区间顺次相接时合段，无指向
  的选项只与同样无指向的相邻选项合段。
- **合并清单（JSONL）**：无任何争议时按旧端 `sender`、`record_no`、副本
  起点数值序输出；相邻区间旧端连续且新端落在同一记录并连续递增时合为一条，
  没有声明时交付空清单，可直接回灌 `build_ledger`。
- 所有区间为半开区间，起点非负、长度为正，一律十进制字符串，副本位可超
  int64。全程按区间流式处理，中间状态落在临时 SQLite 工作库：不逐副本展开，
  内存不随任一整稿或热点记录的声明数增长。两输出路径相同、任一目标已存在或
  目录缺失即报错，不覆盖现有文件，目标路径不出现半成品。

可复跑的小例子：`python3 examples/approval_example.py` —— 同一组数据演示
可共同出账（清单可回灌）与待协调（旧端、新端争议并存）两种结果。


## 夹具与测试

`fixtures/`：

- `two_sides_mid_big/`：left/right 两边都有同值(5 与 10)，中间组(值 10)总权重
  `2^63+15`，超过 64 位；全局总量 `2^63+23`。
- `duplicate_identity/`：`alpha`/`alpha_copy`(同身份同内容，幂等)、
  `alpha_conflict`(同身份异内容，拒绝)、`beta_same_rows`(不同身份同内容，分别贡献)。
- `unknown_tail/`：未知值末组，含缺席值在未知组前的插入位。
- `correction/`：`aaa_first` 排最前，其 v2 版本使后续记录秩整体平移 +6。

`tests/test_dataset.py` 共 24 个用例，要点：

- 独立小数据展开模型逐页(所有位置×所有长度)、逐值(含空并列组插入位)交叉核对；
  单记录内部切分(`slice(3,4)` → 副本位 `[3,7)`)。
- 更正前头分片后：近末页与并列区间同时平移，更正后全集再与展开模型逐页核对；
  并用 SQL 跟踪日志 + 未更正分片行指纹证明更正没有重读/重写其他分片。
- 更正失败(逆序新版本)后旧库可查且内容不变；重开后查询、幂等声明、更正均可用。

`tests/test_ledger.py` 共 19 个用例，要点：

- 逐副本展开参照模型：小样例检查两端占用不同偏移时的承接孔洞、拆分与合并，
  对照明细与地区合计；随机两期数据 + 随机清单全量对照模型，
  并按侧汇总还原该期各地区总权重。
- 末尾才出现的冲突(重叠/越界/找不到端点/坏行)不留下可交付文件与临时文件；
  重复声明算冲突，首尾相接合法，空行计入行号。
- 大权重(2^63 级、10^15 级)与 4 万条集中于同一记录的声明仍按区间处理；
  已有目标不覆盖；删除输入库与清单后台账仍可 `verify()` 独立核对。

`tests/test_residency.py` 共 32 个用例，要点：

- 逐副本展开参照模型：随机多期台账链(1~4 份、含同地区/跨地区转列、退出与
  再新增) + 随机请求(含空行、重复、相交)，交付行与模型全量对照。
- 共用期一致性：权重/估值/记录缺失不一致(含总量相等但登记不同)拒绝交付并
  指出共用期；同地区转列换号、变偏移、变估值不重新计时；退出后同号再新增
  不承接；能追到第 0 期只给下限(门槛内「符合」、超门槛「历史不足」)。
- 合并规则：依据端副本位连续且依据相同才合段(含跨父片段落到同一新增明细)，
  依据副本位跳跃或明细不同则分开；热点记录 3000 段同地区转列合成一段、
  2000 段交替来源逐段分开。
- 大副本位(2^63 级)精确；坏行/找不到记录/越界指出请求行且不交付；已有目标
  不覆盖、不留临时文件；台账只读且事后仍可 `verify()`。

`tests/test_approval.py` 共 29 个用例，要点：

- 逐副本展开参照模型：从三份台账的 transfer 明细逐位展开三稿指向，按审批
  规则逐位判定并按合段规则分组；25 组随机「原批件 + 两份小步修订稿」与交付
  文件全量对照，覆盖可出账与待协调两种结果，可出账清单回灌 `build_ledger`
  后仍可 `verify()`。
- 判定规则：双稿一致(含都撤回)、单稿变更/撤回采用、双稿都变且不同(含撤回对
  改派)记旧端争议；规格 D 例的新端争议只覆盖重叠 `[2,4)` 且能定位两个占用者；
  同一旧端记录不同位置算不同占用者；旧端争议位不参与新端检查且不掩盖其他
  新端争议；争议段相接合段、占用者集合变化则分段。
- 登记不符(权重/估值/未知标记/缺记录，含旧端)指出稿、端、记录且不交付；
  输出路径相同、目标已存在、目录缺失、台账缺失或非台账均报错且不留临时文件。
- 大副本位(2^63 级)精确；热点记录 4 万条声明：可出账合 1 条清单、新端争议合
  1 段、交替旧端争议 2 万段，均按区间流式处理，常驻内存约 40MB。
